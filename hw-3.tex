    \begin{question}{Cookie Connoisseur}
        \begin{part}
            Batch sizes: $S = [1, 3, 4]$ \\
            Cookies: $n = 6$

            \begin{itemize}
                \item Greedy would give the largest batch first, making the next batches two 1's, so it would be $4 + 1 + 1 = 6$, or 3 boxes.
                \item Better: get two batches of 3, $3 + 3 = 6$, or 2 boxes.
                \item Greedy fails because it takes the max value, leaving a remainder that can only be filled by ones.
            \end{itemize}
        \end{part}
        \begin{part}
            \[
            \mathit{cook}(S[\,], i, n) = \begin{cases}
                \min\big(1 + \mathit{cook}(S[\,], i, n - S[i]),\ \mathit{cook}(S[\,], i - 1, n)\big), & S[i] \le n \land i \neq 1 \\
                \mathit{cook}(S[\,], i - 1, n), & S[i] > n \land n \neq 0 \\
                n, & n = 0 \lor i = 1
            \end{cases}
            \]
        \end{part}
        \begin{part}
            For the parameters, $S[\,]$ is the ordered list of batch sizes, $i$ is the current batch size, expecting to start at the end of $S[\,]$, and $n$ is the number of cookies requested. We expect $n$ to be greater than or equal to zero. If the current batch size is less than $n$, we return the minimum number of boxes between continuing with the current size (incrementing the total by one) and the next size down. If the current batch size is greater than $n$, we call the next size down. Finally, our base case is $n = 0$ or $i = 1$, where we return $n$ to end the recurrence.
        \end{part}
        \begin{part}
            $S = [1, 3, 4]$, $n = 6$
        \end{part}
        \begin{part}
            A $\text{length}(S) \times (n + 1)$ matrix, with the rows as the batch sizes in $S$ in increasing order.
        \end{part}
        \begin{part}
            First, we fill column 0 with 0s in every row (because 0 coookies need 0 boxes).
            Fill row 1 from 0...$n$ with the value j (because only single cookies are available).
            For each row from 2 up to length(S), we fill the columns from 1...$n$ left to right. 
            If the batch size $>$ the current column, we store the value of the row above in the same column.
            If the batch size $<=$ the current column, we store the minimum of $1 +$ the value in the same row at the column and the value in the row above in the same column.
            Each cell depends on the cell above and to its left.
            The solution is the bottom right cell.
            
            ----

            First, fill row 1 with the corresponding value from $0\ldots n$. Then, fill column 1 with $0$. Then, starting from the second row and second column (if it exists) do the following procedure:
            \begin{enumerate}
                \item If the row value is greater than the current column value, then take the value of the row above.
                \item Otherwise, take the minimum between $1 + A[row][S[i] - row]$ and $A[row - 1][column]$
            \end{enumerate}
